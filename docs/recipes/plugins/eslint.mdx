ESLint plugins execute JavaScript in the linter process. This recipe installs a pinned security plugin without lifecycle scripts, snapshots the resulting toolchain and lock file, then analyzes a read-only source file in a resource-bounded worker with no network access.

## Prepare the linter

The setup verifies the package integrity values recorded by npm before the toolchain is snapshotted:

```sh
msb run --name eslint-plugin-base --replace \
  --cpus 1 --memory 768M --root-disk 2G \
  --max-duration 5m \
  --script prepare='set -eu
    mkdir -p /opt/linter /work /out
    cd /opt/linter
    npm init -y >/dev/null
    npm install --ignore-scripts --save-exact \
      eslint@10.8.0 \
      eslint-plugin-security@4.0.1

    grep -Fq "sha512-nuKKvN+oIBO0koN7Tm7dlkmnkc21mtt0QJLwAKzjLq14y6lRTdVG36MZHJ8eQHwdJMwZbQNMlPOYedMq/oVJvQ==" package-lock.json
    grep -Fq "sha512-/lZCkOxPOWaf1jXAqgICrS8St3BMBccIPvhOSUYuV6VCr1o5nFVG998FnTLt6w2Nxb8Uo0nM8fzmnhp+GY/aEg==" package-lock.json
    node --version | grep -Fx "v22.23.2"
    npm ls --depth=0 eslint eslint-plugin-security

    cat > /work/eslint.config.cjs <<"EOF"
const security = require("/opt/linter/node_modules/eslint-plugin-security");
module.exports = [security.configs.recommended];
EOF

    cat > /opt/linter/verify-report.cjs <<"EOF"
const report = require(process.argv[2]);
const rules = new Set(report.flatMap(file => file.messages.map(message => message.ruleId)));
const expected = ["security/detect-child-process", "security/detect-eval-with-expression"];
for (const rule of expected) {
  if (!rules.has(rule)) throw new Error(`missing ${rule}`);
}
console.log(expected.join(", "));
EOF

    cat > /opt/linter/probe-network.cjs <<"EOF"
const socket = require("node:net").connect(443, "example.com");
socket.on("connect", () => process.exit(0));
socket.on("error", () => process.exit(1));
socket.setTimeout(2000, () => process.exit(1));
EOF

    chown node:node /out' \
  --entrypoint prepare \
  node:22.23.2-bookworm-slim

msb snapshot create eslint-plugin-runtime \
  --from eslint-plugin-base \
  --integrity \
  --force
msb snapshot verify eslint-plugin-runtime
```

`--ignore-scripts` prevents npm `preinstall`, `install`, and `postinstall` hooks. The plugin itself remains executable code and will run when ESLint loads it in the worker.

## Create a test target

This deliberately unsafe file triggers two rules from `eslint-plugin-security`:

```sh
cat > suspicious.cjs <<'EOF'
const childProcess = require("node:child_process");
const command = process.argv[2];
childProcess.exec(command);
eval(process.argv[3]);
EOF
```

## Analyze it offline

Mount the source read-only, run the plugin as the image's unprivileged `node` user, assert the expected findings, and independently probe the worker's network policy. Running non-root also makes the process limit enforceable:

```sh
msb run --name eslint-plugin-worker --replace \
  --from-snapshot eslint-plugin-runtime \
  --cpus 1 --memory 384M \
  --no-net --security restricted \
  --rlimit nproc=64 --rlimit nofile=128 --rlimit fsize=10485760 \
  --max-duration 30s \
  --user node \
  --mount-file ./suspicious.cjs:/work/suspicious.cjs:ro \
  --script lint-offline='set -eu
    cd /work

    if (printf x >> suspicious.cjs) 2>/dev/null; then
      echo "source unexpectedly writable" >&2
      exit 1
    fi
    echo "source read-only"

    /opt/linter/node_modules/.bin/eslint \
      --format json \
      suspicious.cjs > /out/eslint-report.json
    node /opt/linter/verify-report.cjs /out/eslint-report.json

    if node /opt/linter/probe-network.cjs; then
      echo "network unexpectedly reachable" >&2
      exit 1
    fi
    echo "network blocked"' \
  --entrypoint lint-offline
```

The worker should print:

```text
source read-only
security/detect-child-process, security/detect-eval-with-expression
network blocked
```

Stop the worker before exporting its plugin-controlled report. Copy it into a fresh private directory, reject links and unexpected file types or sizes, and only then parse it on the host:

```sh
msb stop eslint-plugin-worker

eslint_output_dir=$(mktemp -d "${TMPDIR:-/tmp}/msb-eslint.XXXXXX")
chmod 700 "$eslint_output_dir"
eslint_report="$eslint_output_dir/report.json"

msb cp eslint-plugin-worker:/out/eslint-report.json "$eslint_report"
test ! -L "$eslint_report"
test -f "$eslint_report"
test -s "$eslint_report"
test "$(wc -c < "$eslint_report")" -le 1048576
node -e 'const report = require(process.argv[1]); console.log(report[0].messages.map(message => message.ruleId))' "$eslint_report"
```

For a real project, replace `--mount-file` with a read-only source mount such as `--mount-dir ./src:/work/src:ro`, then change the ESLint target from `suspicious.cjs` to `src`.

<Warning>
  An npm plugin can read every file exposed to its process, allocate memory, spawn subprocesses within its limits, and write elsewhere in the guest. Mount only the inputs it needs, keep them read-only, enforce duration and concurrency limits, and export only known report paths. Add `--max-warnings 0` if findings must fail a CI job; the plugin's recommended rules report warnings by default.
</Warning>

## Cleanup

```sh
msb rm -f eslint-plugin-base eslint-plugin-worker
msb snapshot rm eslint-plugin-runtime
rm ./suspicious.cjs "$eslint_report"
rmdir "$eslint_output_dir"
```
