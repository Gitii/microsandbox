Terraform providers are executable plugins that Terraform Core starts as separate processes and talks to over RPC. This recipe caches a pinned provider in a verified snapshot, then applies a self-contained configuration with the provider, configuration file, and network all constrained.

## Create a configuration

The `random` provider needs no external API, so it can demonstrate the complete provider lifecycle offline:

```sh
cat > main.tf <<'EOF'
terraform {
  required_providers {
    random = {
      source  = "hashicorp/random"
      version = "3.7.2"
    }
  }
}

resource "random_pet" "demo" {
  length = 2
  prefix = "microsandbox"
}

output "generated_name" {
  value = random_pet.demo.id
}
EOF
```

## Prepare the provider

Initialize Terraform while networking is available. The generated dependency lock file records the signed provider package checksums and is captured with the installed provider in the snapshot:

```sh
msb run --name terraform-plugin-base --replace \
  --cpus 1 --memory 512M --root-disk 2G \
  --max-duration 5m \
  --copy-file ./main.tf:/work/main.tf \
  --workdir /work \
  --script prepare='set -eu
    terraform init -input=false
    terraform providers
    test -s .terraform.lock.hcl
    install -d -o 65534 -g 65534 /out
    chown -R 65534:65534 /work' \
  --entrypoint prepare \
  hashicorp/terraform:1.13.5

terraform_lock_dir=$(mktemp -d "${TMPDIR:-/tmp}/msb-terraform-lock.XXXXXX")
chmod 700 "$terraform_lock_dir"
terraform_lock="$terraform_lock_dir/.terraform.lock.hcl"

msb cp terraform-plugin-base:/work/.terraform.lock.hcl "$terraform_lock"
test ! -L "$terraform_lock"
test -f "$terraform_lock"
test -s "$terraform_lock"
test "$(wc -c < "$terraform_lock")" -le 65536
grep -Fq 'provider "registry.terraform.io/hashicorp/random"' "$terraform_lock"
grep -Fq 'version     = "3.7.2"' "$terraform_lock"

msb snapshot create terraform-plugin-runtime \
  --from terraform-plugin-base \
  --integrity \
  --force
msb snapshot verify terraform-plugin-runtime
```

`terraform init` should report `Installed hashicorp/random v3.7.2 (signed by HashiCorp)`. Review the private `$terraform_lock` export before continuing. For a real project, copy the reviewed file beside the configuration as `.terraform.lock.hcl` and commit it; Terraform uses its recorded provider checksums on future initializations. The provider itself does not execute until the offline, non-root worker starts below.

## Apply offline

The current configuration and reviewed lock file are mounted over their prepared copies read-only. The worker runs as unprivileged UID/GID `65534`, writes state only to the fresh guest layer, starts the provider to inspect its schema, applies the resource, verifies a second plan has no changes, and proves that outbound HTTPS remains unavailable:

```sh
msb run --name terraform-plugin-worker --replace \
  --from-snapshot terraform-plugin-runtime \
  --cpus 1 --memory 384M \
  --no-net --security restricted \
  --rlimit nproc=64 --rlimit nofile=128 --rlimit fsize=16777216 \
  --max-duration 1m \
  --user 65534:65534 --env HOME=/tmp \
  --mount-file ./main.tf:/work/main.tf:ro \
  --mount-file "$terraform_lock:/work/.terraform.lock.hcl:ro" \
  --script apply-offline='set -eu
    cd /work

    for input in main.tf .terraform.lock.hcl; do
      if (printf x >> "$input") 2>/dev/null; then
        echo "$input unexpectedly writable" >&2
        exit 1
      fi
    done
    echo "configuration and lock file read-only"

    if wget -q -T 2 -O /dev/null https://example.com 2>/dev/null; then
      echo "network unexpectedly reachable" >&2
      exit 1
    fi
    echo "network blocked"

    terraform providers schema -json > /tmp/provider-schema.json
    grep -Fq '"'"'"random_pet"'"'"' /tmp/provider-schema.json

    terraform apply -auto-approve -input=false > /tmp/apply.txt
    grep -Fq "Apply complete! Resources: 1 added" /tmp/apply.txt

    generated_name=$(terraform output -raw generated_name)
    case "$generated_name" in
      microsandbox-*) printf "generated: %s\n" "$generated_name" ;;
      *) echo "unexpected output: $generated_name" >&2; exit 1 ;;
    esac

    terraform plan -detailed-exitcode -input=false > /tmp/plan.txt
    grep -Fq "No changes" /tmp/plan.txt
    echo "second plan: no changes"

    mkdir -p /out
    terraform output -json > /out/outputs.json' \
  --entrypoint apply-offline
```

The generated suffix changes on every fresh worker, but the shape of the result is stable:

```text
configuration and lock file read-only
network blocked
generated: microsandbox-<adjective>-<animal>
second plan: no changes
```

Stop the worker before exporting its plugin-controlled output. Copy it into a new private directory, reject links and unexpected file types or sizes, and only then inspect it:

```sh
msb stop terraform-plugin-worker

terraform_output_dir=$(mktemp -d "${TMPDIR:-/tmp}/msb-terraform-output.XXXXXX")
chmod 700 "$terraform_output_dir"
terraform_output="$terraform_output_dir/outputs.json"

msb cp terraform-plugin-worker:/out/outputs.json "$terraform_output"
test ! -L "$terraform_output"
test -f "$terraform_output"
test -s "$terraform_output"
test "$(wc -c < "$terraform_output")" -le 65536
grep -F '"value": "microsandbox-' "$terraform_output"
```

<Warning>
  Real providers commonly need API credentials and network access, and Terraform state or outputs may contain secrets. Use a deny-by-default network policy with the smallest required allowlist, inject credentials through the [secrets workflow](/sandboxes/secrets), and export only reviewed artifacts. Never copy an untrusted worker's entire state directory onto the host.
</Warning>

## Cleanup

```sh
msb rm -f terraform-plugin-base terraform-plugin-worker
msb snapshot rm terraform-plugin-runtime
rm ./main.tf "$terraform_output" "$terraform_lock"
rmdir "$terraform_output_dir" "$terraform_lock_dir"
```

Any reviewed `.terraform.lock.hcl` that you copied beside a real configuration is intentionally outside this cleanup and should remain in source control.
